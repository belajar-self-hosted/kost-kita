# Rencana Remediasi CI/CD KostKita

Diperbarui 4 November 2026 berdasarkan pemeriksaan GitHub REST API, output terbaru LXC/Docker storage yang diberikan pemilik, validasi lokal, serta probe ingress read-only. Environment staging dan variabelnya dilaporkan telah dikonfigurasi pemilik; nilainya belum bisa dibaca tanpa autentikasi GitHub. Perubahan berada pada branch `codex/cicd-production-remediation` dan belum merged ke main. Tidak ada deployment, migrasi, restart, atau perubahan runtime dari sesi ini.

## Status readiness

- **TESTING/STAGING READY: BELUM SIAP.** Workflow lama masih disabled dan target LXC/runner cocok. Workflow remediasi belum ada di GitHub. Pemilik melaporkan Environment staging dan variabel sudah dikonfigurasi; pembacaan terautentikasi belum tersedia. Docker free disk/inode sudah dilaporkan di atas threshold, tetapi service/deployment path aktual dan data dummy belum diverifikasi; ingress masih memiliki mismatch keamanan.
- **PRODUCTION READY: TIDAK SIAP.** Backup dan restore tetap wajib sebelum pemakaian operasional, selain verifikasi data, migration compatibility, ingress, capacity, secrets, observability dan rollback.
- **Backup testing: DEFERRED — ACCEPTED RISK.** Pemilik menerima risiko kehilangan seluruh data percobaan. Tidak ada backup atau restore yang diklaim tersedia/teruji. Tidak ada volume/database yang dihapus.

## Langkah berikut

1. Ambil output runtime CT 10026 tanpa pager: Compose services, health DB/scheduler/worker, RAM/CPU, deployment path dan image/revision SHA. Disk/inode Docker sudah dilaporkan pemilik; ulangi pada DockerRootDir bila kapasitas berubah. Jangan tampilkan .env.
2. Pastikan data hanya dummy/testing. Jangan aktifkan otomatis jika ada data operasional nyata.
3. Minta pemilik ingress meninjau listener dashboard Traefik 8080, api.insecure, Docker provider/socket, firewall dan route Cloudflare.
4. Verifikasi melalui GitHub sesi terautentikasi bahwa Environment `staging` dan variabel sesuai laporan pemilik. Pertahankan Repository variable `KOSTKITA_DEPLOYMENT_ENABLED=false`; jangan mengaktifkan workflow.
5. Setelah workflow remote dan data target ditinjau, pemilik dapat mengikuti aktivasi bertahap pada Deployment & Rollback Plan. Mengubah flag menjadi true membuat CI main berikutnya berpotensi melakukan deployment.
6. Sebelum production: backup off-node, retention/integrity, restore rehearsal, RPO/RTO, migration plan, capacity, monitoring, ingress security dan rollback rehearsal harus selesai.

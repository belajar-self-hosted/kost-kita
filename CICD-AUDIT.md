## Status implementasi lokal

Pada branch kerja `codex/cicd-production-remediation`, workflow deployment kini hanya menerima keberhasilan workflow `tests` tepercaya pada commit `main`, tanpa dispatch manual atau GHCR. Build dan aktivasi diikat ke tested SHA; deploy script memverifikasi identitas runner/LXC yang dapat dilihat dari dalam container, Compose target/volume/network, image labels, env-file mode/owner, kapasitas disk/inode, migration status aktif dan kandidat, scheduler registry, health/SHA endpoint dan asset hash. Kegagalan pasca-aktivasi mencoba mengaktifkan image sebelumnya; tidak ada migrasi otomatis, perubahan volume atau prune global. CI juga menjalankan regression tests dan actionlint.

Temuan repo yang telah ditangani belum mengubah keadaan GitHub atau LXC. Snapshot Actions pukul 20:21 WIB mencatat workflow legacy ID `405389177` masih active; akses untuk menonaktifkan workflow tidak tersedia. Branch protection `main`, required checks dan environment protection belum diverifikasi/diatur. Docker daemon workstation tidak tersedia untuk build image lokal. Identitas runner/LXC, schema DB, backup/restore, ingress, serta rollback rehearsal tetap BLOCKED atau UNVERIFIED; deployment production belum READY. ## Source, build, dan konsistensi

`actions/checkout` memakai workspace default, lalu `rsync --delete` mengubah `/opt/kostkita/src` secara in-place sebelum build. Ini bukan `git pull`: branch aktif, remote, konflik merge, `safe.directory`, dan permission Git pada direktori target tidak dapat disimpulkan atau diwajibkan sebagai mekanisme pipeline. `.git` dan `.env*` dikecualikan; source tujuan bukan bukti checkout Git bersih dan berpotensi parsial bila sync gagal. Container yang sudah berjalan memakai image, bukan bind mount source, sehingga build gagal **tidak otomatis** merusak proses lama; source staging tetap berubah dan keselamatan keadaan sebelumnya tidak terjamin.

[Dockerfile:47](https://github.com/belajar-self-hosted/kost-kita/blob/9b4fa27a0126254cdfe3ba41bf2d5403520f0b8a/Dockerfile#L47) memakai `composer.lock`, `composer install --no-dev`, `npm ci` dengan `package-lock.json`, Vite build dan platform check; Node 22 dan PHP 8.3 didefinisikan oleh image. Versi aktual, durasi, disk, RAM, CPU dan ownership target belum diukur. Tag base image mutable dan `build --pull` berarti SHA source saja tidak menjamin build identik. Konfigurasi production aktual dan manifest/aset yang disajikan belum dibuktikan. CI memakai `npm install`, sementara production memakai `npm ci`; uji production image dan PostgreSQL secara terpisah.

`rsync` mempertahankan `.env` lama di source; Compose memuat `../.env` lalu `.env` opsional untuk app dan scheduler ([compose.yaml:28](https://github.com/belajar-self-hosted/kost-kita/blob/9b4fa27a0126254cdfe3ba41bf2d5403520f0b8a/compose.yaml#L28), [compose.yaml:62](https://github.com/belajar-self-hosted/kost-kita/blob/9b4fa27a0126254cdfe3ba41bf2d5403520f0b8a/compose.yaml#L62)). File kedua, jika ada, dapat mengesampingkan nilai file pertama; `--env-file` pada CLI juga dipakai untuk interpolasi Compose dan tidak membuktikan environment runtime efektif. Keberadaan serta dampaknya belum diverifikasi; jangan cetak nilai rahasia.

## Temuan dan prioritas

- **Kritis — gerbang kepercayaan belum lengkap:** dispatch bypass CI; event asal dan repository tidak dibatasi, sementara runner berpotensi memiliki akses produksi. Verifikasi branch protection, hak dispatch, pemetaan runner, dan eksekusi aktual sebelum menganggap deploy aman.
- **Tinggi — aktivasi tidak atomik dan migrasi mendahului aktivasi:** `compose up` dapat mengganti beberapa service secara bertahap; tidak ada release SHA, rollback atau uji kompatibilitas schema. Migrasi dapat mengubah DB sebelum app lama berhenti.
- **Tinggi — serialisasi tidak mencakup semua ref dan urutan commit:** deployment manual/ref lain atau aktor host dapat bertabrakan; CI yang selesai tidak berurutan dapat mengaktifkan versi lebih lama.
- **Tinggi — status sukses belum setara kesehatan produksi:** tidak memeriksa SHA aktif, aset, route publik, scheduler atau queue; DB status bukan readiness lengkap.
- **Sedang — konfigurasi env ganda, resource bersama, dan menunggu DB tanpa batas:** file lama dapat override; build pada host produksi dapat menghabiskan resource; loop dapat menggantung. Kondisi aktual belum diketahui.

Langkah verifikasi dan kriteria selesai ada di [REMEDIATION-PLAN.md](REMEDIATION-PLAN.md). Tidak disarankan registry atau runner terpisah sebagai prasyarat.

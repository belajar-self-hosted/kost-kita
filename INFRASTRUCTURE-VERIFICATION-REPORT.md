## Pemeriksaan runtime read-only yang perlu diulang

Output awal berhenti pada pager systemd; ulangi dari node PVE dengan pager dimatikan:

    pct exec 10026 -- sh -lc 'hostname; ip -br addr; df -h; df -i; free -h; nproc'
    pct exec 10026 -- sh -lc 'docker ps --format "table {{.Names}}\t{{.Status}}\t{{.Image}}"; docker compose ls'
    pct exec 10026 -- sh -lc 'systemctl --no-pager --type=service --state=running | grep -E "actions.runner|docker"'
    pct exec 10026 -- sh -lc 'systemctl show actions.runner.belajar-self-hosted-kost-kita.kost-kita.service -p ActiveState -p User -p WorkingDirectory -p FragmentPath'
    pct exec 10026 -- sh -lc 'for p in /opt/kostkita /opt/kostkita/releases /opt/kostkita/.env; do if test -e "$p"; then stat -c "%U %G %a %n" "$p"; else echo "$p missing"; fi; done'

Do not cat .env, print interpolated Compose output, or inspect full container config that may contain environment values. Docker socket access is highly privileged even for read-only commands.

## Gateway / ingress access

Read-only access is needed to gateway CT 10080 and Cloudflare Zero Trust to match hostname, tunnel connector, Traefik router/service and origin IP/port. Do not change route, firewall or gateway services during audit.

    pct exec 10080 -- hostname
    pct exec 10080 -- ip -br addr
    pct exec 10080 -- docker ps --format 'table {{.Names}}\t{{.Status}}\t{{.Image}}'
    pct exec 10080 -- docker inspect traefik --format '{{json .Config.Cmd}} {{json .HostConfig.PortBindings}} {{json .Mounts}}'

Never inspect cloudflared Environment or paste tunnel token. Share only sanitized router hostname/rule/entrypoint/service URL and connector/origin metadata. On this workstation, the route to 192.168.0.26 used en9; if using Tailscale, read the existing peer tailnet IP and route without changing networking.

## GitHub access

Authenticated read-only access is needed for Actions permissions, runner ID/labels/status/group, workflow permissions and detailed branch policy. Do not paste credentials. Safe commands from the owner's authenticated shell:

    gh auth status
    gh api repos/belajar-self-hosted/kost-kita/actions/permissions
    gh api repos/belajar-self-hosted/kost-kita/actions/permissions/workflow
    gh api repos/belajar-self-hosted/kost-kita/actions/runners --jq '.runners[] | {id,name,status,labels:[.labels[].name]}'
    gh api repos/belajar-self-hosted/kost-kita/environments
    gh api 'repos/belajar-self-hosted/kost-kita/rulesets?includes_parents=true'

Workflow old is already disabled, so Actions write is not currently required for that mitigation. Recheck no-run state and disabled status before enabling the new staging workflow. Do not share token, password, .env, APP_KEY, cloudflared token, backup or user data. Backup inspection is deferred for testing and mandatory before production.
